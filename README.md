# Stateful RAG update

## What changed

The old version kept the FAISS vector store only in `st.session_state`.

The updated version persists:

- FAISS index: `data/faiss_store/`
- Indexed-source metadata: `data/state.json`

When a new Streamlit session starts, the saved FAISS index is loaded automatically.

Chat history is intentionally kept in `st.session_state`, so a public deployment does not accidentally expose one user's conversation to another user.

## Run

```bash
streamlit run app.py
```

## Local result

You can:

1. Add PDFs / YouTube videos.
2. Close or refresh the browser.
3. Open a new session.
4. The previously indexed knowledge base will be restored.

## Important deployment note

This uses the local filesystem. That is persistent only when the host provides persistent storage.

Streamlit Community Cloud uses ephemeral application storage, so a container restart/redeploy can still remove `data/`.

For production/cloud persistence, keep the same RAG pipeline but replace the persistence functions with a durable backend such as:

- Supabase/PostgreSQL + pgvector
- S3-compatible object storage for the FAISS files
- another persistent database/object store

For an interview, the key design change is:

`st.session_state (volatile) -> persistent storage (durable) -> FAISS reload on startup`

## Safety note

LangChain's FAISS `load_local()` requires `allow_dangerous_deserialization=True` because the docstore uses pickle. Only load the index files generated by your own application or another trusted source.
